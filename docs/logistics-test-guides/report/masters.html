Section 01

01What Masters does & how to read this guide

logistics.masters is the domain's reference-data layer — 42 registered masters that every downstream module (pricing, sales-crm, booking, shipment, operations, tracking) references via fields.Reference("logistics.…"). It is read-mostly: most masters have no commands and are driven through generic CRUD. The exceptions are the carrier network (approval governance) and two sync-not-seed masters (UN/LOCODE, sailing schedule). Cross-ERP masters — country, city, UOM, party, currency — live in the platform (res.*), not here.

The three real commands (everything else is generic CRUD)

carrier governance : logistics.carrier.approve → approved+active · emits logistics.carrier.approved
                 : logistics.carrier.reject  → rejected+inactive · emits logistics.carrier.rejected
schedule sync     : logistics.sailing.schedule.sync → idempotent upsert of sailings (sync-not-seed)

Two classifications you set on the carrier network

carrier_type (logistics.carrier)

  • shipping_line · airline · road_transporter
  • rail_operator · nvocc
  • mode_id is required; identity is delegated to res.partner

approval_state (Feature 08 governance)

  • draft → submitted → approved | rejected
  • Default approved — governance is off unless opted in
  • Opt in via masters.governance.enabled_models

Section 04 · Scenario C — the guard deep-dive

04Validation guards — the refusals that must hold

Half of testing reference data is confirming it refuses malformed rows. This module raises on exactly two masters — the dangerous-goods taxonomy and the vendor-service catalogue — via pre-create / pre-update lifecycle hooks. Each row below trips a real hook and states the exact ValueError string.

⚠ Not every master hook is a validator — carrier / agent / provider create hooks only DEFAULTThe pre.logistics.carrier.create, …carrier.agent.create and …provider.create hooks do not reject bad input — they default the delegated res.partner shadow's country_id + email (and, for carrier, apply the governance gate). Only haz.class and vendor.service raise ValueError. Do not expect a refusal from a carrier create with a missing partner field — it is silently completed.

Where the guards live

  • haz.class — pre.…create + pre.…update (level ↔ parent invariant)
  • vendor.service — pre.…create + pre.…update (validity window)
  • carrier — approve / reject commands guard on a target row

Read-only masters have no guards

  • Most of the 42 masters are pure CRUD reference rows
  • is_standard_locked=true is a UI contract, not a command-layer block
  • Commodity's "UN number when dg_flag" is a docstring rule, not an enforced hook
