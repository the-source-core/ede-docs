# Internationalization

Capture each user's locale and timezone as first-class data: a BCP-47 language master, a per-user language reference, and timezone-aware datetime display in the web client.

```python
# Give a user a language preference.
user = env.models["res.user"].browse(user_uuid)
english = env.models["res.language"].search([("code", "=", "en-US")])[0]
user.write({"language_id": english.id})
```

`res.language` is the shared master every domain references; `res.user.language_id` records each user's choice, falling back to `DEFAULT_LANGUAGE_CODE` when unset.

---

## What you get

-   **`res.language`** — BCP-47 language master. Fields: `code` (unique, e.g. `en-US`, `fr`, `hi`), `name`, `native_name`, `iso_639_1_code`, `iso_639_2_code`, `direction` (`ltr` / `rtl`), `is_active`. Ships seeded with ~90 common locales.
-   **`res.user.language_id`** — a `fields.Reference` to `res.language` on every user (nullable; `on_delete="set null"`).
-   **`res.user.timezone`** — an IANA timezone (e.g. `Asia/Kolkata`, `UTC`) used to render datetimes in the user's local time.
-   **Timezone-aware datetime display** — the backend serializes datetimes as UTC ISO strings with an explicit `+00:00`; the web client converts them to the user's timezone for display and back to UTC on input.
-   **Admin UI** — Settings → Localization → Languages.

## How to use it

### Set a user's language

```python
hindi = env.models["res.language"].search([("code", "=", "hi")])[0]
env.models["res.user"].browse(user_uuid).write({"language_id": hindi.id})
```

### Read a user's language with a fallback

`language_id` is nullable, so fall back to the configured default when it's unset:

```python
user = env.models["res.user"].browse(user_uuid)
lang_code = user.language_id.code if user.language_id else settings.DEFAULT_LANGUAGE_CODE
```

### Display a datetime in the user's timezone

The backend always stores and emits UTC. The web client formats it into the user's timezone with the datetime helpers in `src/frontend/src/utils/datetime.ts`:

```ts
import { formatDateTime } from "@/utils/datetime";

// utcIso comes from the API as e.g. "2026-06-19T10:00:00+00:00"
const label = formatDateTime(utcIso, user.timezone); // "Jun 19, 2026, 3:30 PM IST"
```

The companion helpers `toInputLocal` / `fromInputLocal` convert between a UTC value and a naive picker input, so date/time fields edit in local time and round-trip to UTC.

### List the active languages

```python
languages = env.models["res.language"].search([("is_active", "=", True)])
```

Use this to populate a language picker in your own UI.

## Configuration

| Setting | Default | What it controls |
|---|---|---|
| `DEFAULT_LANGUAGE_CODE` | `en` | Fallback locale when a user has no `language_id`. |
