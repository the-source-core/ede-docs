Section 01

01What Pricing does & how to read this guide

The pricing module is the RMS — the single authoritative source for every commercial price. A pricing.rate is a priced offering (buy or sell) for a service on a lane; charge lines (pricing.rate.line) carry the components, optionally per leg segment. Rates group under pricing.contract, are sourced ad-hoc via pricing.spot.request, and every amendment forks an immutable pricing.rate.version. Status is workflow=True — transitions are owned by foundation.workflow rows, not free writes.

The three state machines you will observe

Rate, contract and spot-request each carry a governed lifecycle on a workflow=True status field. Watch the statusbar on each form header.

rate    : draft → pending_approval → approved → suspended | expired → archived  (↘ rejected)
contract: draft → active → suspended ⇄ reactivate  | expired | terminated
spot    : pending → responded → selected  | expired | cancelled

Two orthogonal classifications set at rate creation

rate_type & rate_source

  • rate_type — buy (vendor cost) / sell (customer price)
  • rate_source — contract · tariff · spot · promotional · agent · manual · api_feed

margin_risk_level (predictive)

  • safe ≥ 8% · watch 5–8% · risk < 5%
  • negative_risk — margin amount < 0 (billing below cost)
  • Thresholds config-driven (PM-008/PM-010); defaults 5% / 8%

Section 03 · Scenario A

03The margin engine & the guards that must hold

Half of testing pricing is confirming it refuses bad input. First the margin classification thresholds; then eight negative checks that each trip a specific ValueError (or PermissionError).

Margin classification thresholds (defaults; config-driven per PM-008/PM-010)

BandConditionRouting effect on submit
safemargin % ≥ 8.0Auto-approve rule (priority 10) → approved on submit.
watch5.0 ≤ margin % < 8.0Auto-approve — but visibly flagged for review.
riskmargin % < 5.0Risk rule (priority 30) → pending_approval to pricing.approver.
negative_riskmargin amount < 0Routes to approval regardless of percent — needs senior sign-off (BR-010).

Negative checks — each must be refused with the real message

#ActionExpected refusal (verbatim)✔Trace
1submit a rate with no charge lines.“Rate must have at least one charge line before submission.”BlockedRM-001
2submit a rate whose valid_to is already past.“Rate validity period has already expired — extend the validity window (valid_to) before submitting this rate for approval.”BlockedRM-009
3submit a rate whose key fields + lines duplicate an active rate.“A rate with identical key fields already exists: <RATE-№>. Duplicate rates are not allowed …”BlockedBR-015
4Rate owner runs approve on their own rate.“Maker-checker violation: you cannot approve your own rate.”BlockedWF-001
5Edit a locked header field (e.g. currency_id, mode_id, valid_to) on a pending/approved rate.“Rate is locked while its approval case is PENDING or APPROVED — use Amend (Phase 2) to fork a new version or Suspend …”BlockedBR-011
6Create / edit / delete a charge line under a locked rate.“Cannot modify pricing.rate.line — parent rate's approval case is PENDING/APPROVED. Use Amend (Phase 2) on the parent rate or Suspend it.”BlockedBR-011
7Write a line where unit_rate < minimum_selling_amount.“unit_rate <v> is below the minimum selling amount <msp>.”BlockedMAR-004
8suspend a rate that is still draft (not approved).“Only approved rates can be suspended.”BlockedWF-013
⚠ Amend is the escape hatch, not a header editTo change a locked rate, run pricing.rate.amend (reason mandatory — omitting it raises “amendment_reason is required when amending a rate (BR-017, VER-003).”). Amend forks a pricing.rate.version snapshot and resets the rate to draft for re-editing. Only approved or suspended rates may be amended; archive is the terminal end-of-life move (status archived, active=False).
